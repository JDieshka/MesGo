# 🔒 Решение проблемы с доступом к камере и микрофону

## 🐛 Проблема

При открытии приложения по адресу `http://192.168.1.156:8080` браузер блокирует доступ к камере, микрофону и screen share с ошибкой:
```
Access denied: Permission denied
```

## 🔍 Причина

Браузеры (Chrome, Firefox, Safari, Edge) требуют **Secure Context** (HTTPS) для доступа к медиа-устройствам:
- `getUserMedia()` - камера и микрофон
- `getDisplayMedia()` - screen share
- `MediaRecorder` - запись аудио/видео

**Исключение:** `http://localhost` и `http://127.0.0.1` работают без HTTPS.

## ✅ Решения

### Решение 1: Использовать HTTPS (Рекомендуется)

Я создал HTTPS сервер с самоподписанным сертификатом.

#### Шаги:

1. **Пересоберите сервер:**
```bash
cd server
go build -o gotalk-server
```

2. **Запустите сервер:**
```bash
./gotalk-server
```

Сервер автоматически:
- Сгенерирует самоподписанный сертификат (`cert.pem` и `key.pem`)
- Запустится на HTTPS порту 8443
- Добавит IP 192.168.1.156 в сертификат

3. **Откройте в браузере:**
```
https://192.168.1.156:8443
```

4. **Примите самоподписанный сертификат:**

**Chrome:**
- Нажмите "Дополнительно" (Advanced)
- Нажмите "Перейти на 192.168.1.156 (небезопасно)" (Proceed to 192.168.1.156 (unsafe))

**Firefox:**
- Нажмите "Дополнительно" (Advanced)
- Нажмите "Принять риск и продолжить" (Accept the Risk and Continue)

**Edge:**
- Нажмите "Подробности" (Details)
- Нажмите "Перейти на веб-страницу" (Go on to the webpage)

### Решение 2: Chrome Flags (Быстрое решение для тестирования)

Если нужно быстро протестировать без настройки HTTPS:

1. **Откройте Chrome flags:**
```
chrome://flags/#unsafely-treat-insecure-origin-as-secure
```

2. **Добавьте адрес:**
```
http://192.168.1.156:8080
```

3. **Включите flag** и перезапустите Chrome

⚠️ **Внимание:** Это решение только для разработки! Не используйте в продакшене.

### Решение 3: mkcert (Доверенные локальные сертификаты)

Для более профессионального решения используйте `mkcert`:

1. **Установите mkcert:**
```bash
# macOS
brew install mkcert

# Windows
choco install mkcert

# Linux
sudo apt install mkcert
```

2. **Создайте локальный CA:**
```bash
mkcert -install
```

3. **Сгенерируйте сертификат:**
```bash
cd server
mkcert 192.168.1.156 localhost 127.0.0.1
```

Это создаст файлы:
- `192.168.1.156+2.pem` - сертификат
- `192.168.1.156+2-key.pem` - приватный ключ

4. **Переименуйте файлы:**
```bash
mv 192.168.1.156+2.pem cert.pem
mv 192.168.1.156+2-key.pem key.pem
```

5. **Запустите сервер:**
```bash
./gotalk-server
```

Теперь браузер будет доверять сертификату (не нужно нажимать "Продолжить").

## 📋 Сравнение решений

| Решение | Сложность | Безопасность | Продакшен |
|---------|-----------|--------------|-----------|
| HTTPS + самоподписанный сертификат | Средняя | Средняя | ⚠️ Только для dev |
| Chrome Flags | Очень низкая | Низкая | ❌ Только для dev |
| mkcert | Средняя | Высокая | ✅ Для dev/staging |
| Let's Encrypt + домен | Высокая | Очень высокая | ✅ Для продакшена |

## 🎯 Рекомендация

**Для разработки:** Используйте **Решение 1** (HTTPS + самоподписанный сертификат)

**Для продакшена:** Используйте **Let's Encrypt** с реальным доменом

## 🔧 Обновление main.go для HTTPS

Нужно обновить `main.go`, чтобы использовать HTTPS сервер:

```go
// В функции main() замените:
log.Fatal(http.ListenAndServe(port, router))

// На:
if err := startHTTPSServer(&router, ":8443"); err != nil {
    log.Fatal("HTTPS server failed:", err)
}
```

## 📊 Проверка работы

После настройки HTTPS проверьте:

1. **Камера работает:**
   - Откройте видеозвонок
   - Разрешите доступ к камере
   - Должно появиться видео с камеры

2. **Микрофон работает:**
   - Откройте голосовой звонок
   - Разрешите доступ к микрофону
   - Должна работать запись голоса

3. **Screen share работает:**
   - Во время звонка нажмите "Демонстрация экрана"
   - Выберите экран/окно
   - Должна появиться трансляция

## 🐛 Если всё ещё не работает

### Проверьте консоль браузера (F12):

**Ошибка: "NotAllowedError: Permission denied"**
- Решение: Примите самоподписанный сертификат или используйте HTTPS

**Ошибка: "NotFoundError: Requested device not found"**
- Решение: Проверьте, что камера/микрофон подключены и не используются другим приложением

**Ошибка: "NotReadableError: Could not start video source"**
- Решение: Перезагрузите браузер или компьютер

### Проверьте настройки браузера:

**Chrome:**
```
chrome://settings/content/camera
chrome://settings/content/microphone
```

Убедитесь, что для `https://192.168.1.156:8443` разрешён доступ.

## ✅ Итог

Для работы звонков, видеочата и screen share на `192.168.1.156` необходимо использовать **HTTPS**. 

Самое простое решение - использовать самоподписанный сертификат, который автоматически генерируется при запуске сервера.

После настройки HTTPS все функции будут работать корректно!

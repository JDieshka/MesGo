# 🔧 Критическое исправление: Loop Variable Capture в Go

## 🐛 Описание проблемы

**Симптомы:**
- При клике на чат выделялись ВСЕ чаты сразу
- Сообщения отправлялись во ВСЕ чаты одновременно
- Все чаты отображали одинаковые данные (имя, аватар, последнее сообщение)

**Корень проблемы:**
Классическая ошибка Go - **Loop Variable Capture** (захват переменной цикла).

## 📖 Что такое Loop Variable Capture?

В Go до версии 1.22 переменная цикла `for _, item := range items` создаётся ОДИН раз и переиспользуется на каждой итерации. Если вы берёте указатель на эту переменную (`&item`), все указатели будут ссылаться на ОДНУ И ТУ ЖЕ переменную, которая в конце цикла будет содержать данные последнего элемента.

### Пример проблемы:

```go
// ❌ НЕПРАВИЛЬНО
var result []*Chat
for _, chat := range chats {
    result = append(result, &chat) // Все указатели ссылаются на одну переменную!
}
// В результате все элементы result будут указывать на последний chat из цикла
```

### Правильное решение:

```go
// ✅ ПРАВИЛЬНО
var result []*Chat
for _, chat := range chats {
    chatCopy := chat // Создаём копию
    result = append(result, &chatCopy) // Каждый указатель ссылается на свою копию
}
```

## 🔍 Где была проблема

**Файл:** `server/chat_api.go`  
**Функция:** `GetUserChatsWithDetailsHandler`

### Было (неправильно):

```go
for _, chat := range chats {
    participants, err := chatRepo.GetChatParticipants(chat.ID)
    // ...
    result = append(result, ChatWithDetails{
        Chat:         &chat,  // ❌ Указатель на переменную цикла!
        Participants: participants,
        LastMessage:  &messages[0],
        UnreadCount:  unreadCount,
    })
}
```

**Результат:** Все чаты в `result` имели одинаковые данные (последнего чата из цикла).

### Стало (правильно):

```go
for _, chat := range chats {
    chatCopy := chat // ✅ Создаём копию
    
    participants, err := chatRepo.GetChatParticipants(chatCopy.ID)
    // ...
    result = append(result, ChatWithDetails{
        Chat:         &chatCopy,  // ✅ Указатель на уникальную копию
        Participants: participants,
        LastMessage:  &messages[0],
        UnreadCount:  unreadCount,
    })
}
```

**Результат:** Каждый чат имеет свои уникальные данные.

## 🎯 Почему это вызывало симптомы

### 1. Все чаты выделялись при клике

Когда сервер возвращал список чатов, все элементы массива содержали одинаковые данные (последнего чата). На фронтенде:

```typescript
// Все чаты имели одинаковый ID (последнего чата)
chats = [
  { id: "uuid-3", name: "Chat 3", ... }, // На самом деле это chat 1
  { id: "uuid-3", name: "Chat 3", ... }, // На самом деле это chat 2
  { id: "uuid-3", name: "Chat 3", ... }, // Это chat 3
]

// При клике на любой чат:
activeChatId = "uuid-3"

// Проверка в Sidebar:
activeChatId === chat.id  // true для ВСЕХ чатов!
```

### 2. Сообщения отправлялись во все чаты

Когда пользователь выбирал чат и отправлял сообщение:

```typescript
// activeChatId был одинаковым для всех чатов
sendMessage(activeChatId, text)

// Сервер получал запрос с одинаковым chatId для всех чатов
// и сохранял сообщение во все чаты
```

## 📚 Другие места с потенциальной проблемой

Проверьте все места, где используется `&variable` в цикле:

### ✅ Правильно (безопасно):

```go
// 1. Создание новой переменной внутри цикла
for _, item := range items {
    var copy Item = item
    result = append(result, &copy)
}

// 2. Использование значений вместо указателей
for _, item := range items {
    result = append(result, item) // Копирование значения
}

// 3. Использование индекса
for i := range items {
    result = append(result, &items[i]) // Указатель на элемент массива
}
```

### ❌ Неправильно (опасно):

```go
// Указатель на переменную цикла
for _, item := range items {
    result = append(result, &item) // Все указатели на одну переменную!
}
```

## 🔧 Альтернативные решения

### Вариант 1: Go 1.22+

В Go 1.22 поведение циклов изменено - переменная цикла создаётся заново на каждой итерации. Если вы используете Go 1.22+, проблема не возникнет.

Проверьте версию:
```bash
go version
```

### Вариант 2: Использование индекса

```go
for i := range chats {
    result = append(result, &chats[i]) // Указатель на элемент массива
}
```

### Вариант 3: Копирование (использовано в этом исправлении)

```go
for _, chat := range chats {
    chatCopy := chat
    result = append(result, &chatCopy)
}
```

## ✅ Итог

**Проблема:** Loop Variable Capture в Go  
**Файл:** `server/chat_api.go`  
**Функция:** `GetUserChatsWithDetailsHandler`  
**Решение:** Создание копии переменной цикла (`chatCopy := chat`)  
**Результат:** Каждый чат теперь имеет уникальные данные

**Симптомы исправлены:**
✅ Чаты больше не выделяются все сразу  
✅ Сообщения отправляются только в выбранный чат  
✅ Каждый чат отображает свои уникальные данные

## 🎓 Выводы

1. **Всегда будьте осторожны с указателями в циклах** в Go (до версии 1.22)
2. **Создавайте копии переменных**, если нужно сохранить указатели
3. **Используйте линтеры** (например, `gosec` или `go vet`) для обнаружения таких проблем
4. **Тестируйте с несколькими элементами** - проблемы с циклами часто проявляются только при наличии нескольких элементов

## 📝 Примечание для разработчиков

Если вы обновите Go до версии 1.22+, эта проблема исчезнет автоматически, так как в новой версии переменная цикла создаётся заново на каждой итерации. Однако код с явным копированием (`chatCopy := chat`) останется корректным и будет работать во всех версиях Go.
